# 设计完善度审核（对照产品目的与已确认决策）

**审核基准：**  
- 目的：可迁移学习能力；AI 是教练；离开 AI 仍会学  
- 边界：中小学全科，先做数学（D-029）  
- V1 精简：D-025…D-028（自动归并、缓建 Goal、Workflow 真表、砍 Stage/Policy 全量/三类 State）  
- **搬运优先（D-030）：** 算法/设计先学成熟体系；自研必须带反馈；设计稿须标明学自/搬运/自研  
- 推进方式：按闭环优先级，不按“先 Migration”

**日期：** 2026-11-15  
**结论：** 原则与模块边界够用；**闭环规格与科目可扩展性明显不足**，按优先级应先补设计，再谈落库。

## P0 — 闭环走不通就先补这些

### 1. 学段 × 科目扩展点（D-029 未落到模型）

**缺口：** Task / Question / KnowledgeIssue / KnowledgeState 仍无稳定的 `school_stage` / `subject`（或等价）维度；知识目录无「学段+科目+知识点」骨架。

**要补的设计产出：**
- 逻辑字段：科目、学段（小学/初中，可再细年级）挂在哪些实体上  
- 目录模型：`Subject` / `KnowledgePoint`（或等价）最小结构——数学填实，语文等占位  
- 约束：禁止数学专用死枚举写死在核心表

### 2. 自动归并算法 v0（D-028 / U-011）

**缺口：** 只定了「要自动」，未定：
- 何时新建 KI vs 挂接已有 KI  
- 相似度/知识点键/题型键用什么  
- UNCONFIRMED 怎么处理  
- 错并后如何拆分（自动修正，仍不靠人点选闸门）  
- 与 Evidence/Finding 的最低输入要求  

**要补：** 一页「归并规则 v0」+ 10～20 道数学样例预期（可先手写）。

### 3. Daily Learning 闭环逐步规格

**缺口：** `learning-workflow.md` 自陈：转换守卫、责任人、异常/恢复未规格化。  
且状态名含 `COLLECTING_RESPONSES`，与「纸上已作答再上传」容易打架。

**要补（按步）：**

| 步 | 须写清 |
|---|---|
| 上传前 | Task 如何创建；科目/学段；是否已完成纸质 |
| 上传/OCR | 多页、模糊、部分失败 |
| 确认 | 谁确认（家长？系统？）；未确认不得归因（已有原则） |
| 诊断 | 批诊断输入/输出；Finding 形状 |
| 自动归并 | 接 D-028 v0 |
| 决策/建议 | 自动生成练习建议的权限级别 |
| 薄干预 | 提示强度、不代做 |
| 验证 | 即时/延迟各产生什么新 Response |
| 状态 | 只更新 KnowledgeState 时依据是什么 |

### 4. OCR 与「不依赖人」的边界

**现状张力：** 基线是「AI 识别 + 人工校正」；产品强调系统少依赖人（D-028）。  

**要补的产品澄清（设计决策）：**
- 识别确认/校正：是否允许家长轻量确认（入口质量）？  
- 哪些步骤**禁止**人工闸门（归并、归因、出练习）？  
- 适配层接口（引擎可换）——选型可后定，接口要先有（U-001 拆两半）。

---

## P1 — 否则会做成「判题工具」而非「学习教练」

### 5. 薄 Intervention + Methodology（服务目的）

V1 无 Stage 树（D-025）可以，但须定义：
- 一次干预最少步骤（提问引导 → 孩子再答 → 验证）  
- 提示强度（NONE→…）如何随成功降低  
- 禁止代做/直接给答案的策略  
- 与「离开 AI 也会学」的关系（成功标准草案）

### 6. Decision 权限钉到闭环

三级权限有概念；闭环里要写死例如：
- 生成练习建议：自动？建议待确认？  
- 与 D-006（目标共定）区分：练习任务 ≠ 人生目标  

### 7. 数学知识目录 v0

U-012：先数学内容，结构必须能挂初中数学及其他科目。

### 8. 验证如何证明「会了」

即时/延迟/迁移验证：题从哪来、与原错题/KI 的关系、失败后是否回写 KI/State。

---

## P2 — 与目的相关、可并行澄清

### 9. Thinking 等在 V1 的交代

目的含思维能力，但 V1 缓建 ThinkingState。  
**要补一句产品策略：** V1 用 Finding 类型/引导过程事件做弱信号，还是数学闭环暂不评价思维、文档明确「V1.1」？避免实现时静默丢掉目的。

### 10. Workflow 真表最小集（D-027）

升 U-007 为正式 D；U-006 最小发布校验；Daily Learning 一张 DefinitionVersion 即可。

### 11. 成功标准（非 AI 使用量）

「离开 AI 也会学」的可观察信号草案（延迟验证通过率、提示强度下降、独立作答比例等）——哪怕 V1 只采其中 1～2 个。

## 建议的设计完善顺序（闭环优先）

```text
1. 学段/科目字段 + 目录骨架（数学填实）     ← D-029
2. 闭环逐步规格（含 OCR 人机边界）
3. 自动归并规则 v0 + 样例                       ← D-028 / U-011
4. 薄干预 + 决策权限 + 验证规格（教练性）
5. KnowledgeState 内容 schema v0               ← U-010 子集
6. Workflow 最小定义（真表）                   ← D-027
7. 再进入可执行 Migration / 原型实现
```
