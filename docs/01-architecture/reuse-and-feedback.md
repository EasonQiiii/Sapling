# 搬运优先与反馈进化（D-030）

## 原则

1. **先搬运，不先发明。** 算法、知识体系、流程骨架优先采用已有成熟体系（课标、ITS、知识追踪、OCR 开源、工作流标准等），做适配层接入。  
2. **角色是搬运工。** 默认工作是：选型 → 理解边界 → 映射到本产品对象 → 写适配与约束；不是从零发明「家庭学习专用理论」。  
3. **非造不可才自研。** 仅当成熟体系无法覆盖产品硬约束（纸质优先、证据事实、自动归并不靠人闸门、中小学全科扩展等）时，才新增自有算法/对象。  
4. **自研必须带反馈系统。** 每个自研轮子要有：输入日志、输出、对错/效用信号、迭代指标与回滚方式，使轮子越用越好用。  
5. **文档须标明来源。** 凡算法/目录/流程设计，写清「学自何处 / 适配了什么 / 自研了什么」。

## 本项目优先学习的成熟体系（首批清单）

| 领域 | 优先学习 / 可搬运 | 本产品适配点 |
|---|---|---|
| 学段科目目录 | 国家课程标准知识点结构；常见教材章节树 | `subject` + `school_stage` + knowledge_point；先填数学 |
| 掌握与追踪 | BKT / 简化 mastery 阈值；Knowledge Space 思想 | KnowledgeState 更新；不一次发明新追踪理论 |
| 错因与归并 | 数学错因/错误分类研究；实体解析（同一问题聚类） | Finding→KI **自动**归并算法 v0 |
| 辅导流程 | ITS / Cognitive Tutor / 苏格拉底提问套路 | 薄 Intervention + Methodology 提示强度 |
| 间隔验证 | 间隔复习（如 SM-2/FSRS 类思想） | 延迟验证排程（可先极简） |
| OCR | PaddleOCR 等成熟引擎 | **适配层**；引擎可换（U-001） |
| 流程骨架 | 有限状态机 / BPMN 式节点 | Workflow 真表；Daily Learning 一条定义 |
| 证据与事实 | 事件溯源 / append-only 审计惯例 | Evidence、Event、Outbox（已有方向） |

清单可增，不可无来源地「拍脑袋算法」。

## 自研反馈系统最低要求

每个自研算法组件至少具备：

| 要素 | 说明 |
|---|---|
| `algorithm_id` + `version` | 可追溯版本 |
| 输入快照引用 | Evidence / Finding / Context refs |
| 输出业务对象 | 如 KI link、StateRevision |
| 效用信号 | 延迟验证对错、人工抽检（抽检≠闸门）、撤销/拆分事件 |
| 指标 | 错并率、漏并率、提示强度下降、独立作答占比等（与 P5 一致，不用 AI 时长） |
| 变更流程 | 新版本灰度 → 对比指标 → 保留或回滚 |

## 审核时怎么用

补任何 P0/P1 设计时：先填「学自 / 搬运 / 自研」三栏；缺学自栏的设计稿视为不合格。
