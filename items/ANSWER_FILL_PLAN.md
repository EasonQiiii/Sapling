# 五年级上册题库补答案计划（给 agent 执行）

> 对象：`items/sujiao-g5-vol1.yaml`，共 395 题，当前 38 题有 `answer`，357 题待补（其中 8 题为开放或活动类，见 B00）。
> 本计划只负责 `answer` / `answer_note` 字段。不改 `id`、`task`、`figure`、`kp_main`、`kp_other`、`thinking`、`source`。

## 0. 总原则

1. **题面与图形是唯一依据**。`task` 和 `figure` 不得修改。发现题面或图形有误，记入 `ISSUES` 清单交人工裁决，不要自行"修正"。
2. **坐标一律由脚本计算，不凭目测**。平移、旋转、对称的终点坐标必须用脚本算出，再写入 `answer`。
3. **答案形式**
   - 图形类（题目给出 `figure`，要求画出或补全）：`answer` 用与 `figure` 相同的结构化格式（`type: points`，`shapes` 列表）。
   - 数值、结论、运动方式类：`answer` 写成字符串，简洁写出结果和关键依据。
   - 活动、讨论、开放类（如倡议书、调查、设计游戏）：`answer` 保持 `null`，`answer_note` 必须写明完成标准，不编标准答案。
   - 答案中的小数统一保留到 2 位以内，去掉浮点误差（如 `0.5900000000000001` 写成 `0.59`）。
4. **不做多余修改**。每个 batch 只改动本批次的 `answer` 和 `answer_note`。

## 1. 分工与流程（每个 batch 一轮）

每批 15–35 题，按下列三个角色执行。角色尽量由不同 agent 承担，避免自己验证自己。

| 步骤 | 角色 | 输入 | 输出 |
|---|---|---|---|
| 1 | **Author（作答）** | 本批 `task` + `figure` + `source` | 草稿 `answer` / `answer_note` 写入 sidecar 文件 |
| 2 | **Verifier（盲测）** | **只能**拿到本批 `task` + `figure`（导出的 blind JSON，不含任何答案） | 独立作答，写入 `*_independent.json` |
| 3 | **Reconciler（对账）** | Author 草稿 + Verifier 结果 + 脚本对比报告 | 逐条裁决：一致 / 采纳某方 / 上报人工 |
| 4 | **Merge（合并）** | 通过对账的 sidecar | 写入 `sujiao-g5-vol1.yaml`，跑校验，提交 git |

### 为什么 Verifier 必须盲测
单元 1 的盲测（`checks/unit1-blind-run/`）已经证明：独立作答会发现作答者的错误。例如 G5V1-040 中，盲测把"直角边向右、向下"误读成"向右、向上"，导致落点象限错误。YAML 原答案是对的，但如果没有盲测，这类错误很难被发现。

### 并行与冲突
- 不同 agent 不得同时直接写 `sujiao-g5-vol1.yaml`，否则互相覆盖。
- 每个 batch 在 `items/answers/<batch>.yaml` 下先写 sidecar（只含 `id`、`answer`、`answer_note`）。
- 只有 Reconciler 或人工负责合并进主文件，并在合并后跑一次校验。

## 3. 每批的执行步骤（给 agent 的操作清单）

### 步骤 A：Author 作答
1. 读取本批次 `task`、`figure`、`source`、`kp_main`。
2. 对每题分类：**图形题 / 数值题 / 结论题 / 开放或活动题**。
3. 图形题：用脚本根据 `figure` 计算变换后的坐标，写成结构化 `answer`。
4. 数值题：列出算式和结果，结果带单位。
5. 开放或活动题：`answer: null`，`answer_note` 写完成标准，格式参照 G5V1-016、042–046。
6. 结果写入 `items/answers/<batch>.yaml`。

### 步骤 B：导出盲测输入
运行导出脚本（待实现），生成 `items/answers/<batch>/blind.json`，只包含 `id`、`task`、`figure`。**不得**把 Author 草稿或 YAML 原答案放进去。

### 步骤 C：Verifier 盲测
Verifier 仅根据 `blind.json` 作答，输出 `items/answers/<batch>/independent.json`。作答要求：
- 图形变换必须写出"绕哪点、什么方向、多少度"或"向哪个方向平移几格"。
- 每个终点坐标要写出来，便于对比。

### 步骤 D：对账
1. 运行对比脚本（待实现）：对图形题比较坐标集合，对数值题比较关键数字。
2. 对所有不一致的题目逐条裁决，并在 `items/answers/<batch>/reconcile.md` 中记录：
   - 结论：采纳 Author / 采纳 Verifier / 人工裁决
   - 理由：一句话说明依据（如"Verifier 误读方向，已用坐标核对"）
3. 出现以下任一情况，直接上报人工，不自行裁决：
   - 题面与图形数据不一致；
   - 题目本身有歧义，两种读法都合理；
   - 无法用坐标或算式验证的结论。

### 步骤 E：合并与提交
1. 把通过对账的 `answer` / `answer_note` 写入主文件 `sujiao-g5-vol1.yaml`。
2. 运行 `python3 items/checks/validate_g5v1.py`，必须 0 错误。
3. 检查本批次 ID 范围内只有 `answer` / `answer_note` 发生变化（可用 `git diff` 确认）。
4. 提交，提交信息格式：`G5V1 answers B0x: <单元> <ID区间>`。
