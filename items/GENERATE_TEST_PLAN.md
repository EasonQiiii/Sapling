## 1. 硬性规则（违反任何一条，该题必须重写或删除）

1. **题面自包含**：题干必须包含作答所需的全部数据。禁止依赖教材插图、表格、线路图、图中数据，禁止写“见教材第 X 页”。
2. **禁止示例值**：禁止写“按教材常见数值示例”“不作绝对答案”“数据以图为准”。这类题直接删除，不得修补。
3. **题目只有一个可核对的答案**，或答案空间被题干明确限定。若答案不唯一，题干必须写清判定标准（如“写出一个符合要求的例子”），并在 `answer_note` 中给出完成标准。
4. **自编题标记**：`source.origin` 固定为 `self`，`source.note` 写明批次与知识点，例如 `自编测试题，依据 A4-09（覆盖补齐，第二批 S-B02）`。
5. **`figure` 一律为 `null`**。本批题不做图形题。
6. **`kp_main` 必须是 spine 中的 KP ID**（格式 `[A-D]\d-\d{2}`）。不得使用 CAP-xx，不得使用 `null`，不得新增 KP。
7. **不改 spine**。若发现某个 KP 无法出题，记入本文件第 7 节“上报”，跳过该 KP，不得擅自修改 spine（spine 修改需走 `MATH_STD_V1_FREEZE.md` §8）。
8. **不推送**。只提交到本地分支，不执行 `git push`，除非用户明确批准。
9. **不从 LO/DD 派生反例题**（`IC-DERIVE-01`）。不得从 spine 的 `learning_objectives` / `diagnostic_dimensions` 中的辨析或否定措辞直接出"判断/辨析/反例"类题。此类素材只能取自 `knowledge-spine/outer/misconception-bank.yaml`；正/反比例判定题只以比值或乘积恒定为判据（`IC-DERIVE-02`）。

## 2. 题目格式

每题字段（与已有题保持一致，字段顺序见 `items/new/build_S_B01.py`）：

```yaml
- id: G5V1-S073
  source:
    origin: self
    note: 自编测试题，依据 A4-09（覆盖补齐，第二批 S-B02）
  task: 题干（中文，全角标点）。
  kp_main: A4-09
  kp_other: []
  thinking: 按步骤做          # 五档之一，见下
  figure: null
  answer: 标准答案（字符串）
  answer_note: 完成标准或解题依据（可选，但推荐写）
```

`thinking` 只能取以下五个值之一：

| 档位 | 取值 | 含义 |
|---|---|---|
| 1 | 认出来就做 | 直接套用概念或公式 |
| 2 | 按步骤做 | 有明确步骤，按部就班 |
| 3 | 先选方法或先把情境翻译成数学关系 | 需要先判断用哪种方法或列出关系 |
| 4 | 还要说明理由 | 计算后必须给出依据 |
| 5 | 自己把几个关系串起来 | 综合两个以上关系，自己组织推理 |

**每个知识点 3 题的分档建议**（与 `build_S_B01.py` 的 `thinking_for` 一致，可按需要调整）：
- 第 1 题：档位 2 或 3（基础题）
- 第 2 题：档位 4（说明理由）
- 第 3 题：档位 4 或 5（综合题）

整批要求：4–5 档不少于 50%，1 档不少于 10%。若某知识点的内容天然适合第 1 档，可在第 1 题上用档位 1，但每批总体仍需满足上述比例。

## 4. 每批执行流程（五步，顺序执行，不可跳步）

以下以 S-B02 为例，其余批次替换批次名与 ID 范围即可。

### 步骤 A：作者起草

1. 新建 `items/new/build_S_B02.py`，参照 `items/new/build_S_B01.py` 的结构：
   - `DRAFTS` 列表，每项 `(kp, task, answer, answer_note 或 None)`；
   - `thinking_for(kp, slot)` 按第 2 节分档；
   - `build()` 生成条目，ID 从 `G5V1-S073` 起；
   - `__main__` 写出 `items/new/S-B02.yaml`。
2. 每个答案必须在写入前用 Python 或手算复核一遍，尤其是数值计算。
3. 运行 `python3 items/new/build_S_B02.py`。

### 步骤 B：导出盲测输入

1. 生成 `items/new/S-B02/blind.json`，内容**只能包含** `id` 和 `task`，不得包含 `answer`、`answer_note`、`kp_main`、`thinking`。
2. 导出后用 `python3 -c` 检查 JSON 中没有 `answer` 字段。

### 步骤 C：盲测（独立子代理）

1. 启动一个 `generalPurpose` 子代理，指令要点：
   - 只读取 `items/new/S-B02/blind.json`，不得打开其他文件（尤其是 `items/new/S-B02.yaml`、主库、任何 `answers/` 或 `reconcile` 文件），不得搜索仓库；
   - 逐题独立作答，每题给出最终答案和一两句理由；
   - 结果写入 `items/new/S-B02/independent.json`，格式为 `[{"id": "...", "answer": "..."}]`，条数与输入一致；
   - 完成后只回复“已写入 N 条”，不回复答案内容。
2. 每批只启动一个子代理。

### 步骤 D：对账

1. 逐题比对草稿答案与盲测答案，结论一致的记为“通过”。
2. 结论不一致时，按以下顺序处理：
   - 草稿计算或理解错误 → 修改草稿答案，记入 `reconcile.md`；
   - 盲测理解错误（如位值、正负号方向读错） → 保留草稿，记入 `reconcile.md`，说明盲测错在哪里；
   - 题干有歧义，导致两人理解不同 → **改写题干**使其唯一，再重新盲测该题；若一次改写仍不唯一，直接删除该题，并换一道题（ID 顺延，不留空号）。
3. 对账结果写入 `items/new/S-B02/reconcile.md`，每个分歧一行，包括：题号、分歧内容、处理结论、理由。
4. 对账完成后，更新 `build_S_B02.py` 并重新生成 `S-B02.yaml`。

### 步骤 E：校验

在合并前，必须同时满足：
- `python3 items/checks/validate_g5v1.py` 输出 `errors: 0  warnings: 0`；
- 新增条目的 `kp_main` 全部存在于 spine；
- 新增条目的 `thinking` 全部为第 2 节五个值之一；
- 新增条目的 `source.origin` 全部为 `self`，`figure` 全部为 `null`，`answer` 全部非空；
- 新增条目的 ID 无重复，与主库已有 ID 不冲突；
- 第 4–5 档占比 ≥ 50%，第 1 档占比 ≥ 10%（不满足则回到步骤 A 补题）；
- 批次覆盖的每个知识点恰好达到目标题数（每点 3 题，S-B06 按缺口）。

### 步骤 F：合并与提交

1. 把 `items/new/S-B02.yaml` 的内容按文本方式插入主库 `items/sujiao-g5-vol1.yaml`，位置为顶层 `_note_figures:` 行之前（与 S-B01 的合并方式相同）。**不要用 `yaml.dump` 重写整个主库**，以免改变已有题目格式。
2. 合并后再跑一次 `python3 items/checks/validate_g5v1.py`，必须 0 错误 0 警告。
3. 提交一次，提交信息格式：

## 6. 已知易错点（来自 S-B01 与 R01 的经验）

1. **正负号与方向**：涉及“向东/向西”“零上/零下”时，题干要写清正方向，并分开问“记作多少”和“位置在哪里”。S-B01 的 S011 因为只问一个而导致草稿把位置写错。
2. **“至少”“最多”等限定词**：容易让人理解不同（R01 的 129 题就因此被删）。题干需要写清楚要计算的是哪一种数量。
3. **数位与位值**：小数位的题（如 3.45 中的 4 在哪一位）盲测容易误读，出题时注明“十分位”“百分位”等，并在 `answer_note` 中写明位值。
4. **答案不唯一的题**：优先设计成“写出一个符合要求的例子”，并在 `answer_note` 写完成标准。不要让两个合理答案都会被判错。
5. **算式类题**：草稿答案的每个数都要复算。S-B01 的 S056 草稿写成了同乘 2，而盲测写成了同除以 10，两者都对但需要统一写法。
6. **盲测不是权威**：盲测结论与草稿不同时，要重新推导，而不是按多数决定。盲测也会出错（如 S063 的位值误读）。
7. **不要复用教材题的题目文字**：新题要原创，但知识点必须与 spine 一致。

## 7. 上报与跳过

- 题目自身存在争议，连续两次改写仍无唯一答案：删除该题，换题。
